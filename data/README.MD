# Data

Папка `data/` содержит все данные, используемые ML-частью проекта.

Главная идея очень простая:


raw → interim → processed


То есть:

1. Получаем исходные данные организаторов.
2. Кладём их в `raw/`.
3. Обрабатываем данные.
4. Промежуточные результаты при необходимости сохраняем в `interim/`.
5. Полностью подготовленные для модели данные сохраняем в `processed/`.

Структура:


data/
├── README.md
├── raw/
│   └── .gitkeep
├── interim/
│   └── .gitkeep
└── processed/
    └── .gitkeep


## `raw/` — исходные данные

Здесь находятся данные в том виде, в котором мы получили их от организаторов.

Например:


data/raw/
├── train.csv
├── test.csv
├── stops.csv
└── routes.csv


Конкретные названия файлов зависят от структуры датасета.

### Главное правило

**Файлы внутри `raw/` не изменяем вручную.**

Если необходимо удалить столбец, исправить тип данных, объединить таблицы или выполнить другую обработку — это должно происходить программно.

Нельзя делать так:


Открыли train.csv
↓
что-то исправили руками
↓
сохранили train.csv


Иначе другой участник команды не сможет воспроизвести эти изменения.

Правильно:


data/raw/train.csv
        ↓
код preprocessing
        ↓
data/interim/train_cleaned.parquet


Таким образом, `raw/` всегда остаётся исходной точкой, из которой можно заново построить весь датасет.

## `interim/` — промежуточные данные

Здесь находятся результаты промежуточной обработки данных.

Допустим, организаторы дали несколько таблиц:


validations.csv
stops.csv
routes.csv


Мы объединили их:


validations
     +
stops
     +
routes
     ↓
merged_validations.parquet


Такой файл можно сохранить:


data/interim/merged_validations.parquet


Другой пример.

Было:


data/raw/train.csv


После очистки:


data/interim/train_cleaned.parquet


После добавления географической информации:


data/interim/train_with_geo.parquet


### Когда использовать `interim/`

Используем эту папку, если промежуточный результат:

- долго вычисляется;
- используется несколько раз;
- нужен нескольким скриптам;
- удобен для отладки;
- позволяет не запускать весь preprocessing заново.

### Важное правило

Любой файл из `interim/` должен быть возможно получить заново из `raw/` с помощью нашего кода.

То есть удаление всей папки:


data/interim/


не должно уничтожить уникальную информацию.

## `processed/` — готовые данные для ML

Здесь находятся данные, полностью подготовленные для использования моделью.

Например:


data/processed/
├── train.parquet
├── validation.parquet
└── test.parquet


К этому моменту мы уже могли:

- очистить данные;
- обработать пропуски;
- привести даты к правильному формату;
- объединить таблицы;
- добавить информацию об остановках;
- добавить информацию о маршрутах;
- создать временные признаки;
- создать lag-признаки;
- создать rolling-признаки;
- подготовить train/validation/test.

После этого ML-код должен иметь возможность работать непосредственно с `processed/`.

Условно:


data/processed/train.parquet
             ↓
          train.py
             ↓
           model


### Чем `processed/` отличается от `interim/`

`interim/`:

> Мы ещё обрабатываем данные.

`processed/`:

> Данные уже готовы к использованию моделью.

Например:


raw/
    validations.csv
    stops.csv

        ↓ merge

interim/
    validations_with_stops.parquet

        ↓ feature engineering

processed/
    train.parquet
    validation.parquet


## Полный жизненный цикл данных

Пример полного pipeline:


dataset.zip
     ↓
распаковка
     ↓
data/raw/
     ↓
очистка и объединение
     ↓
data/interim/
     ↓
feature engineering
     ↓
data/processed/
     ↓
обучение модели


Код, выполняющий эти преобразования, находится в:


ml/src/


## Что хранится в Git

Сами данные в Git не коммитятся.

В `.gitignore` находятся правила:

gitignore
data/raw/*
data/interim/*
data/processed/*

!data/raw/.gitkeep
!data/interim/.gitkeep
!data/processed/.gitkeep


Поэтому файлы данных:


.csv
.parquet
.xlsx
...


внутри этих директорий не попадут в репозиторий.

`.gitkeep` нужен только для того, чтобы Git сохранил пустые директории.

## Что делать после `git clone`

После клонирования репозитория структура будет выглядеть примерно так:


data/
├── README.md
├── raw/
│   └── .gitkeep
├── interim/
│   └── .gitkeep
└── processed/
    └── .gitkeep


Дальше необходимо самостоятельно получить датасет организаторов и поместить исходные файлы в:


data/raw/


После этого preprocessing должен создавать содержимое:


data/interim/


и:


data/processed/


## Коротко

Если непонятно, куда положить файл, используем правило:

**Файл пришёл от организаторов без наших изменений?**

→ `raw/`

**Это промежуточный результат нашей обработки?**

→ `interim/`

**Это финальный датасет, который можно непосредственно передать модели?**

→ `processed/`

И самое важное:


raw не изменяем вручную
interim можно удалить и пересоздать
processed можно удалить и пересоздать
