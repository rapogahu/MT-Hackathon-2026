# Небольшие задачи до рабочего сервиса

Это порядок разработки по ТЗ 4.2, не перечень уже начатых работ. Для запуска перенеси **одну** задачу в ACTIVE_TASK и поручай её явно. При необходимости дели строку ещё мельче, сохраняя проверяемый результат.

## Текущий маршрут: сначала frontend

Приоритет пользователя — разработка UI. FE-01–04 можно выполнять по зафиксированным DTO с явными тестовыми данными, не дожидаясь прогнозного backend. Это последовательность разработки, а не отмена backend/ML-зависимостей при сдаче продукта.

| ID | Задача | Зависимость | Проверяемый результат |
|---|---|---|---|
| FE-01 | Каркас React/TypeScript/Vite, клиент, DAY и KPI | ТЗ 4.2, Node/npm; готовый API не требуется | Реализован первый экран на fixtures, отдельно проверен HTTP-адаптер; текущая ACTIVE_TASK |
| FE-02 | MONTH/PERIOD/ALL, суммы, CSV и URL состояния | FE-01 | Произвольный диапазон ноября–декабря и согласованный экспорт; fixtures используют тот же контракт |
| FE-03 | MapLibre, справочная геометрия, остановки/участки | FE-02 и валидная выборка из реального справочника | География не придумана, отсутствие схемы обработано; backend нужен только для реальной интеграции |
| FE-04 | Метрики, выбор выпуска и дополнительные состояния | FE-02, контракт metrics | Исторические/отсутствующие метрики подписаны корректно; синтетика явно маркирована |
| FE-05 | Проверка с реальным backend и модельным run | FE-01–04, DEV-05/06/07/11 и ML-04 | api-режим без fixtures, реальные графики/карта/экспорт совпадают по run_id |

FE-01 — ограниченный первый этап, не весь frontend за одну задачу. На FE-03 брать реальные координаты из справочника либо показывать отсутствие геометрии; на FE-04 не выдавать синтетические метрики за качество модели. YEAR не блокирует эти этапы.

## ML-ветка

| ID | Задача | Зависимость | Проверяемый результат |
|---|---|---|---|
| ML-01 | Labels/raw parser, аудит, сетка и маршрут 5 | Исходные данные | Воспроизводимый target, статусы нулей/пропусков и отчёт |
| ML-02 | Seasonal baselines и временная оценка | ML-01 | Прогноз длинного горизонта без чтения будущих лагов |
| ML-03 | Direct CatBoost, Daily TS, ансамбль и сравнение | ML-02 | Компоненты/веса проверены одинаковыми folds; сохранён metrics.json |
| ML-04 | Финальный forecast, metadata и импортная проверка | ML-03 | Собственные 14 640 прогнозов и артефакт воспроизведения |
| ML-05 | CalendarProvider и geolinking interface | ML-01 | Нет фиктивных внешних признаков, неподходящая геопривязка unavailable |

ML-ветка может выполняться командой параллельно разработке web; это не инструкция автоматически запускать субагентов. Для DEV-04/05 до готовности ML допустимы явно синтетические тестовые fixtures. Они не заменяют реальный прогноз в итоговой приёмке. Самостоятельные YEAR, XLSX и настоящий matcher остаются расширениями после MVP.
