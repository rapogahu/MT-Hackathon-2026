## Функциональный объём

### MONTH и PERIOD

- Сохранить рабочий DAY без регрессий.
- MONTH выбирает календарный месяц внутри покрытия run и запрашивает суточные агрегаты. Карта-заглушка и KPI остаются отдельным снимком выбранных `date + hour`.
- PERIOD содержит черновые поля «С»/«По», детализацию `hour|day|week|month` и кнопку «Получить прогноз». До нажатия график, итог и экспорт относятся к последнему успешно применённому диапазону.
- Обе границы включительны; `from <= to`; выход за покрытие не отправляется в API. Быстрые варианты: «Ноябрь», «Декабрь», «Весь период».
- Для 15.11–05.12 ожидаются 504 почасовые точки одного маршрута либо 5 040 точек ALL. На длинном диапазоне по умолчанию используется суточная детализация.
- Показать «Прогноз посадок за выбранный период». Суммировать исходные числа серверных точек/агрегатов до UI-округления, без суммирования направлений карты.

### Все маршруты

- Добавить вариант «Все маршруты»; в HTTP он означает отсутствие query-параметра `route`, а не строку `ALL`.
- DAY/PERIOD hour показывают отдельные серии десяти маршрутов. Для агрегатов также сохраняются отдельные значения маршрутов.
- KPI абсолютного потока за выбранный час равен сумме десяти POINT-записей. Общие процент и индекс не рассчитываются: показывать «См. по маршрутам».
- Добавить таблицу десяти маршрутов с посадками, процентом, индексом и доступностью геометрии. Частичный ответ не подписывать полным итогом.
- Скрытие серии в легенде не меняет итог, фильтр или экспорт.

### Экспорт и URL

- «Скачать CSV» использует `GET /api/export.csv` с закреплёнными `run_id`, route и применёнными границами. По умолчанию выгружаются все часы; опция «Только выбранный час» добавляет `hour`.
- Production/API-адаптер скачивает серверный файл и учитывает безопасное имя из `Content-Disposition`; UI не строит CSV из округлённых точек графика.
- Fixture-адаптер реализует ту же операцию детерминированным development-файлом и сохраняет постоянную маркировку синтетики.
- URL восстанавливает `run`, `route|ALL`, `view`, `date`, `hour`, `month`, применённые `from/to` и `granularity`. Черновые не применённые даты в URL не записывать.
- Смена view/run/route/range не применяет устаревшие ответы. Переходы не должны сдвигать московскую календарную дату.

## Расширение типизированного клиента

Добавить к общему `ForecastDataClient` только операции, предусмотренные Backend-ТЗ:

- расширить существующие `getDay/getPoint`, разрешив `route: number|null` для ALL;
- `getTimeseries({runId, route|null, from, to})`;
- `getAggregate({runId, route|null, from, to, granularity})`;
- `exportCsv({runId, route|null, from, to, hour?})`.

Расширить DTO `TimeseriesResponse`, `AggregatePoint/Response` и результат скачивания. DAY/POINT и metadata не дублировать. HTTP-клиент должен проверяться по фактически сформированным URL, в том числе по отсутствию `route` для ALL.

Fixtures строятся из уже существующего детерминированного генератора и сохраняют согласованность DAY/POINT/TIMESERIES/AGGREGATE/CSV. Агрегат должен совпадать с суммой входящих часов; нули остаются значениями. Development-экспорт не выдаётся за конкурсный submission.
