# Активная задача — FE-01: старт frontend

Статус: **готова к началу разработки, реализация не начата**. Обновлено: 26.09.2026.

Текущий приоритет — frontend. В рамках подготовки этой карточки меняется только документация; следующий запуск разработки выполняет описанный ниже этап. Прежняя DEV-01 сохранена в [BACKEND_TASK.md](BACKEND_TASK.md) и остаётся невыполненной.

## Цель

Создать в корневом `frontend/` первый работающий сценарий: выбор конкретного маршрута, даты и часа → почасовой DAY-график → KPI посадок, относительной загрузки и индекса. Экран должен запускаться без готового прогнозного backend в явно включённом режиме тестовых данных и иметь отдельный HTTP-адаптер для будущего подключения API.

## Объём первого этапа

- React 19 + TypeScript + Vite; ECharts для DAY. MapLibre подключается на этапе карты FE-03, не нужен для запуска FE-01.
- Русскоязычный адаптивный экран: заголовок, выбранный выпуск и период, фильтры, три KPI, график и место под будущую карту с честным состоянием «Карта будет доступна на следующем этапе».
- Все десять конкретных маршрутов доступны. Маршрут 17 без схемы не отключается. ALL, MONTH/PERIOD, CSV, карта и метрики планируются следующими карточками и не должны выглядеть работающими в FE-01.
- Начальный выбор: default run, маршрут 1, первый доступный день run, 08:00; дата ограничена покрытием, час 0–23.
- Выбор точки графика меняет час/KPI. Смена фильтров не применяет устаревший ответ; состояние run/route/date/hour восстанавливается из URL.
- Загрузка, ошибка с повтором, отсутствие опубликованного run, нулевой prediction, вырожденная нормализация. Отсутствие данных не подменять нулём.
- Относительную загрузку и индекс брать из ответа/fixture, не вычислять квантили на frontend.

## Контракт источника данных

Типизированный интерфейс клиента использует только нужные FE-01 операции: список runs, metadata run, продуктовый каталог, DAY и POINT. Типы соответствуют полному Backend-ТЗ, включая nullable metadata и расширенные поля прогноза.

Два явных режима:

| Режим | Поведение |
|---|---|
| `api` (по умолчанию) | HTTP к настроенному API; недоступность/404/503 отображаются как ошибки, без перехода на fixtures |
| `fixtures` (только development/tests) | Детерминированные данные тех же DTO; постоянно видна подпись «Тестовые данные — не прогноз модели» |

Выбор — `VITE_DATA_SOURCE=api|fixtures`, адрес — `VITE_API_BASE_URL`. Запуск fixtures — отдельный npm script, работающий и из PowerShell без Unix-синтаксиса env. Production build должен использовать только api; попытка production-сборки с fixtures завершается ошибкой. Тестовые данные подключаются только в dev/test ветке, а не как резерв после HTTP-сбоя.

Fixtures покрывают все 10 маршрутов, заявленный диапазон 01.11–31.12.2025, 24 часа каждого дня, один фиксированный синтетический UUID run. Нужны согласованные DAY/POINT, нули и отдельные сценарии ошибок/пустого списка runs; задержки для проверки гонок управляются тестами. Допустим детерминированный генератор внутри dev-адаптера; это не ML, не оценка качества и не код расчёта бизнес-показателей в UI.

Компоненты используют общий интерфейс и не знают, какой адаптер выбран. Экран читает расширенные dashboard GET; минимальный внешний `POST /api/predict` не содержит индексов, поэтому не заменяет их. Реализация POST-сервера в эту задачу не входит.

## Планируемые файлы

- `frontend/package.json`, lockfile, `index.html`, TypeScript/Vite config.

- `frontend/src/**/*.test.ts(x)` либо `frontend/tests/` — meaningful tests сценариев.
- `frontend/.env.example`, `frontend/README.md`.
- Минимальные правила `node_modules/`, `dist/`, локальных env в корневом `.gitignore`, если их нет.
- Документация текущей реализации, TESTING, журнал и эта карточка после появления кода.

Конкретные имена компонентов можно уточнить. Не менять Python/backend, SQL, ML, XLSX, вложенный проект и API-контракт ради удобства fixtures. Несовпадение контракта записать, не маскировать.

## Критерии приёмки FE-01

- [ ] Из чистого frontend-окружения воспроизводятся установка по lockfile, dev-сервер, typecheck, build и тесты.
- [ ] Fixtures запускаются отдельной командой без PostgreSQL/ML/backend и имеют постоянную видимую маркировку.
- [ ] API-режим делает запросы предусмотренных форм; run_id закреплён, устаревшие ответы не применяются.
- [ ] В DAY у выбранного маршрута ровно 24 точки, KPI выбранного часа совпадают с ними.
- [ ] Все 10 маршрутов выбираются, включая 5 и 17; недостаток геометрии не скрывает прогноз.
- [ ] Нули, loading, empty-run, API error/retry и вырожденная шкала проверены.
- [ ] Быстрая смена фильтра и восстановление URL проверены без сдвига московской даты.
- [ ] На 360 px и от 1280 px фильтры/график доступны; управление имеет текстовые подписи и работает с клавиатуры.
- [ ] Production не включает автоматическую подмену API и отклоняет режим fixtures.
- [ ] Неготовые функции явно обозначены; FE-01 не объявлен полным выполнением Frontend-ТЗ.
- [ ] README/TESTING фиксируют точные команды, поддерживаемые Node/npm и фактические результаты браузерной проверки.

## Команды, которые должна предоставить реализация

Из `frontend/`: `npm run dev`, `npm run dev:fixtures`, `npm run typecheck`, `npm run build`, `npm test` (один проход без watch), `npm run preview`.

При первом создании проекта исполнитель устанавливает зависимости и формирует lockfile; затем проверяет `npm ci`. Node/npm проверяются перед выбором совместимых версий Vite. Сейчас этих scripts ещё нет — не записывать их выполнение как успешное до реализации.
