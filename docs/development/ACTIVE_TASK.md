# Активная задача — FE-03: MapLibre и справочная географическая навигация

Статус: **готова к началу разработки, реализация не начата**. Обновлено: 26.09.2026.

FE-01 и FE-02 завершены: в корневом `frontend/` работают DAY/MONTH/PERIOD/ALL, KPI, диапазоны, таблица маршрутов, CSV, URL-состояние и 11 тестов. FE-03 развивает этот же экран, заменяя заглушку карты настоящим MapLibre-компонентом. Backend, ML и вложенный `MT-Hackathon-2026/` в этой задаче не изменять.

## Цель

Показать прогноз выбранного часа на справочной схеме маршрута и добавить навигацию по вариантам пути, остановкам и участкам. География помогает ориентироваться, но не меняет смысл прогноза: `prediction`, процент и индекс относятся ко всему маршруту, а не к остановке, направлению или участку.

## Функциональный объём

### Типизированный клиент и данные

- Добавить DTO и методы клиента для:
  - `GET /api/map/routes?date&hour&route?&run_id`;
  - `GET /api/routes/number/{route}/geometry`;
  - `GET /api/routes/number/{route}/directions`;
  - `GET /api/routes/number/{route}/stops?trip_id?&direction_id?`;
  - `GET /api/routes/number/{route}/segments?trip_id?&direction_id?`.
- Прогнозный map-запрос всегда закрепляет текущий `run_id`, `date` и `hour`. В ALL параметр `route` отсутствует; строку `ALL` в HTTP не передавать.
- Разделять прогнозный GeoJSON и справочную геометрию. У справочного `/geometry` нет `run_id` и полей прогноза.
- Сохранять `route`, `route_id`, `trip_id`, `direction_id`, `geometry_id`, периоды действия, `reference_actual_date`, `geometry_source`, `outside_validity_period` и `reference_version` без клиентского переосмысления.
- Остановку идентифицировать парой `geometry_id + stop_sequence`, участок — стабильным `segment_id`. `stop_id` и `trip_short_name=0` не использовать как уникальный путь.
- При смене маршрута или `reference_version` сбрасывать несовместимые direction/stop/segment selections. Устаревшие ответы карты не применять.

### Карта MapLibre

- Установить MapLibre GL JS и заменить существующую заглушку отдельным `ForecastMap` с корректным созданием и уничтожением экземпляра карты.
- Источник подложки задавать настройкой окружения, например `VITE_MAP_STYLE_URL`; ключи не хранить в коде. Для fixture/offline-проверки допустим локальный минимальный стиль без выдуманной картографии. Для внешней подложки сохранить требуемую атрибуцию.
- Отрисовать GeoJSON всех вариантов выбранного маршрута. Вся линия маршрута получает один цвет категории выбранного часового `ForecastPoint`; искусственные градиенты по остановкам, случайные значения и анимация вагонов запрещены.
- Цвета категорий: `very_low #2563EB`, `low #16A34A`, `medium #CA8A04`, `high #EA580C`, `very_high #DC2626`. Цвет дополнить текстовой подписью и индексом; выбранный вариант пути/участок выделять толщиной или обводкой.
- При первой загрузке и смене маршрута выполнять fit bounds по доступной геометрии. Смена часа/даты/направления не должна постоянно сбрасывать пользовательский zoom и положение карты.
- Popup линии показывает маршрут, дату/час, посадки, процент, индекс, направление, период действия и актуальность схемы. При `outside_validity_period=true` обязательно показывать предупреждение.
- На карте и рядом с ней постоянно объяснить: «Прогноз относится к маршруту целиком» и «Схема соединяет остановки из предоставленного справочника».

### Географическая навигация

- Для конкретного маршрута показать selector варианта пути/направления из `/directions`, затем соответствующие остановки и участки.
- Выбор направления ограничивает отображаемые остановки и участки. Выбор остановки центрирует карту и открывает popup; выбор участка выделяет только пару соседних остановок и показывает их названия.
- Под контролами написать: «Географический выбор; прогноз — по маршруту целиком».
- Direction/stop/segment меняют только карту. Они не меняют KPI, график, итог периода, forecast/aggregate-запросы или CSV.
- В ALL географические контролы отключены с подсказкой «Выберите маршрут». Клик по линии или строке таблицы переключает общий фильтр на конкретный маршрут.

### Состояния и отказоустойчивость

- У маршрута без геометрии оставить рабочими график, KPI и экспорт; на карте показать «Геометрия маршрута отсутствует в предоставленном справочнике» и, при наличии точки, «Прогноз доступен».
- В ALL показать только реально доступные линии и пояснить, что схема покрывает часть маршрутов. Не рисовать отсутствующие маршруты.
- Ошибка подложки или map endpoint не должна скрывать исправные график/KPI/экспорт. Для карты показать локальную ошибку и «Повторить».
- Различать loading, пустую геометрию, сетевую ошибку и несовпадение периода действия. Не выдавать пустой массив за ошибку.
- Географическое состояние можно хранить в URL только через стабильные ID. При восстановлении сначала сверить route и `reference_version`; несовместимые параметры удалить, не подбирая похожую остановку.

## Fixture-режим

- Fixture map/directions/stops/segments должны быть согласованы между собой и с текущими route/date/hour; прогнозные свойства берутся из существующего `makeFixturePoint`.
- Географические координаты и последовательности извлечь из предоставленного XLSX для малого числа вариантов, указать происхождение и детерминированный `reference_version`. Не создавать «красивую» произвольную линию.
- Сохранить текущую доступность: маршруты без справочной геометрии остаются без неё. Fixture-баннер «Тестовые данные — не прогноз модели» остаётся видимым; справочные координаты не превращают числовой fixture в модельный прогноз.
- Production/API-режим не переключается на fixture после ошибки.

## Не входит

- Реализация backend map/geometry endpoint и изменение `GTFSRepository` — DEV-07.
- Реальная интеграция frontend с этими endpoint — DEV-10/FE-05.
- Stop-level или segment-level prediction, распределение потока по направлениям, движущиеся вагоны и realtime.
- Метрики модели и selector выпусков — FE-04.
- PostGIS, геокодирование и восстановление трассы по дорогам.

## Критерии приёмки FE-03

- [ ] MapLibre отображает только переданную GeoJSON-геометрию и корректно освобождает ресурсы.
- [ ] Карта использует текущие `run_id/date/hour/route`; смена часа перекрашивает линии без сброса пользовательского масштаба.
- [ ] Все варианты пути получают показатель всего маршрута; stop/segment-level значения не выдуманы.
- [ ] Цвет, легенда, popup и предупреждение `outside_validity_period` соответствуют ТЗ и доступны не только через цвет.
- [ ] Direction/stop/segment корректно связаны стабильными ключами, управляют только географией и сбрасываются при route/reference_version change.
- [ ] Остановка центрируется и открывает popup; участок выделяет ровно пару соседних остановок.
- [ ] ALL не передаёт `route=ALL`, показывает только доступные схемы и предлагает выбрать маршрут для навигации.
- [ ] Маршруты без геометрии не теряют прогноз, график и CSV; пустое состояние честно подписано.
- [ ] Ошибка карты/подложки локальна, имеет retry и не ломает остальные блоки страницы.
- [ ] Fixture-геометрия происходит из справочника и согласована между geometry/directions/stops/segments; production fallback отсутствует.
- [ ] Клик строки таблицы/линии выбирает маршрут; URL не восстанавливает несовместимые географические ID.
- [ ] На 360 px и от 1280 px карта, контролы, popup и пояснения доступны с клавиатуры; нет горизонтальной прокрутки страницы.
- [ ] Регрессия FE-02, TypeScript, тесты и production build проходят; ручная браузерная проверка записана в TESTING/журнал.
