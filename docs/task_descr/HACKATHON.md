# Требования хакатона

Этот файл содержит ограничения и требования, которые Codex должен учитывать при разработке решения.
Не считать рекомендации обязательными, если организаторы явно не обозначили их как обязательные.

## 1. Обязательные требования (MUST)

### Итоговое решение
- Решение должно включать ML/AI-прогнозирование пассажиропотока.
- Итоговый продукт должен быть контейнеризирован и разворачиваться через Docker.
- Веб-сервис должен предоставлять REST/HTTP API для получения прогнозов.
- Должен быть интерфейс/дашборд для анализа прогнозов и визуализации.
- Должен поддерживаться экспорт результатов как минимум в CSV и/или XLSX.

### Производительность
Целевой режим одного экземпляра сервиса:
- 2–4 vCPU;
- 2–4 ГБ RAM;
- сотни RPS;
- p95 latency < 200–300 мс;
- CPU ориентировочно 60–80% под нагрузкой с запасом;
- стабильное использование RAM без swap.

В итоговом README обязательно указать измеренные характеристики производительности решения.
Не заявлять достижение требований производительности без фактического измерения.

### Data Science submission
Финальный прогноз загружается отдельным `submission.csv`.
Формат и правила формирования submission описаны в `PROJECT.md` и `DATA.md`.

## 2. Рекомендуемый стек (SHOULD, не жёсткий запрет)

Предпочитать стек организаторов, если нет причины отклоняться от него:

- Backend: Java 17+; рекомендуется Java 21 LTS.
- Spring Boot 4.0+; рекомендуется 4.1.x.
- Для высокой пропускной способности: Netty / Spring WebFlux.
- Frontend: React 19+, TypeScript 5.x+.
- ML: Python.
- Предпочтительные ML-библиотеки: scikit-learn, LightGBM, PyTorch.
- Инференс в JVM при необходимости: ONNX Runtime / DJL.
- Инфраструктура: Docker, Docker Compose.
- Хранилище: PostgreSQL, ClickHouse или columnar/file storage.
- Карты: MapLibre, Leaflet или Yandex Maps API.

Для первого baseline не добавлять инфраструктуру, backend или frontend, если это не требуется для получения ML-результата прямо сейчас.

## 3. Функциональные требования

Решение должно позволять работать с прогнозом:
- по маршруту;
- по остановке/участку, если такая детализация реализована;
- по временному интервалу;
- с визуализацией динамики;
- с экспортом результата.

Целевая ML-задача хакатона для текущего этапа — прогноз числа посадок на уровне `route × date × hour`.

## 4. Горизонты прогноза

Организаторы описывают:
- краткосрочный горизонт — день с почасовой детализацией;
- среднесрочный — месяц;
- долгосрочный — год (опционально).

Для текущего Data Science submission прогнозный период — один непрерывный интервал:
`2025-11-01 ... 2025-12-31`.

Не интерпретировать "день/месяц" как поступление новых фактических данных внутри ноября–декабря.

## 5. Внешние данные

Допускается/поощряется использование внешних факторов:
- погода;
- календарь и праздники;
- транспортная ситуация;
- события;
- строительство/открытие маршрутов и другие релевантные источники.

Если используется внешний источник:
1. фиксировать источник и ссылку;
2. проверять, была ли информация доступна на момент реального прогнозирования;
3. не использовать будущие факты, которые невозможно было знать заранее.

## 6. Submission limits и дедлайн

- Общее число попыток загрузки на команду в день: 36.
- Успешных попыток: 24.
- В зачёт идёт лучший Data Science score.
- Дедлайн, указанный организаторами: 27 сентября, 23:59 МСК.

Не расходовать попытки на заведомо непроверенные или некорректно сформированные submission-файлы.
